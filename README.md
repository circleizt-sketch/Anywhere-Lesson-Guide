# 어디나지원단 수업 가이드 사용·수정 안내

코딩을 처음 접하는 담당자를 위한 안내입니다. 프로그램을 따로 설치하지 않고도 웹사이트를 확인하고, 간단한 문구와 링크를 수정할 수 있도록 설명합니다.

> **재사용 안내:** 교육자료의 재게시·수정 배포, 별도 사이트 공개, 로고 사용 등은 서울AI재단의 사전 서면 승인이 필요합니다. [허용 범위와 승인 대상 확인](#12-교육자료-및-로고-재사용-안내)

## 1. 웹사이트 주소는 어디인가요?

**GitHub 기본 주소를 사용하는 경우의 접속 주소:**

### https://circleizt-sketch.github.io/Anywhere-Lesson-Plan/

위 주소를 누르면 수업 가이드가 열리는지 확인할 수 있습니다. 주소는 대소문자까지 그대로 사용하세요.

> 실제 배포 주소와 상태는 아래 방법으로 GitHub Pages 설정에서 확인하세요. 커스텀 도메인을 설정했다면 실제 주소가 달라질 수 있습니다.

### 가장 정확한 확인 방법

1. [프로젝트 저장소](https://github.com/circleizt-sketch/Anywhere-Lesson-Plan)를 엽니다.
2. GitHub에 로그인합니다.
3. 화면 위쪽의 **Settings**를 누릅니다. 화면 폭이 좁으면 상단 메뉴의 `…` 안에 있을 수 있습니다.
4. 왼쪽 메뉴의 **Pages**를 누릅니다. [Pages 설정 바로가기](https://github.com/circleizt-sketch/Anywhere-Lesson-Plan/settings/pages)도 사용할 수 있습니다.
5. `Your site is live at ...` 문구와 **Visit site** 버튼이 있으면 그 버튼을 누릅니다.
6. 열린 페이지의 주소창에 있는 주소를 복사해 강사들에게 공유합니다.

**Visit site로 열린 주소가 실제 웹사이트 주소입니다.** GitHub 화면에 이 문구가 아직 없다면 아래 2번을 확인하세요.

### GitHub 주소와 웹사이트 주소는 달라요

| 용도 | 주소 | 무엇을 하는 곳인가요? |
| --- | --- | --- |
| 파일 보관·수정 | https://github.com/circleizt-sketch/Anywhere-Lesson-Plan | `index.html`, README 등이 보이는 관리 화면 |
| 수업 가이드 이용 | https://circleizt-sketch.github.io/Anywhere-Lesson-Plan/ | Pages가 배포되면 강사가 이용하는 웹 화면 |

GitHub의 파일 목록 주소를 강사에게 보내면 수업 화면 대신 코드가 보일 수 있습니다. `localhost:8000`도 다른 사람과 공유하는 웹 주소가 아닙니다.

## 2. 웹사이트가 아직 열리지 않으면 어떻게 하나요?

### 처음 한 번: GitHub Pages 설정 확인

저장소를 관리할 권한이 있는 계정으로 진행하세요.

1. [Settings → Pages](https://github.com/circleizt-sketch/Anywhere-Lesson-Plan/settings/pages)를 엽니다.
2. **Build and deployment** 영역을 찾습니다.
3. **Source**를 **Deploy from a branch**로 선택합니다.
4. **Branch**는 **main**, 옆의 폴더는 **/(root)**로 선택합니다.
5. **Save**를 누릅니다.
6. 잠시 기다렸다가 Pages 화면을 새로고침합니다. 반영에는 몇 분이 걸릴 수 있습니다.
7. **Visit site**가 나타나면 눌러서 확인합니다.

이미 정상 배포 중이면 설정을 바꿀 필요가 없습니다. 다른 배포 방식이 이미 설정돼 있다면 임의로 변경하기보다 담당자에게 확인하세요.

### 여전히 안 열릴 때 확인할 순서

1. 저장소의 **Code** 탭에서 브랜치가 `main`인지 확인합니다.
2. 파일 목록 맨 바깥에 **index.html**이 있는지 확인합니다. ZIP 안이나 하위 폴더 안에만 있으면 안 됩니다.
3. 위의 Pages 설정이 `main`과 `/(root)`인지 확인합니다.
4. 저장소 위쪽의 **Actions** 탭을 엽니다. [Actions 바로가기](https://github.com/circleizt-sketch/Anywhere-Lesson-Plan/actions)
5. Pages 배포 작업이 실행 중이면 기다립니다. 초록색 체크는 성공, 빨간색 X는 실패를 뜻합니다. README 변경 같은 일반 커밋과 Pages 배포 작업은 구분해서 보세요.
6. 빨간색 X가 보이면 해당 작업을 눌러 실패한 단계와 오류 문구를 확인합니다. 화면을 캡처해 담당자에게 전달하면 됩니다.
7. 배포가 성공했는데도 옛 화면이면 Windows는 **Ctrl + Shift + R**, Mac은 **Command + Shift + R**로 강력 새로고침합니다. 또는 시크릿/개인정보 보호 창에서 확인합니다.

**404**는 해당 주소에서 페이지를 찾지 못했다는 뜻입니다. **403**, 회사 보안 안내, 네트워크 차단 화면은 별도의 접근 문제일 수 있으므로 오류 문구를 그대로 확인하세요.

### Custom domain은 꼭 입력해야 하나요?

아니요. 별도로 소유한 도메인이 없다면 **Custom domain은 비워 두세요.**

`Seoul AI Foundation`처럼 기관 이름을 적는 칸이 아닙니다. 실제 소유한 도메인 주소와 DNS 연결 설정이 있을 때만 사용합니다. 기존에 정상 연결된 도메인이 있다면 지우거나 바꾸지 마세요.

## 3. 파일 이름과 역할부터 알아보기

| 파일 | 역할 | 언제 수정하나요? |
| --- | --- | --- |
| **index.html** | 실제 웹페이지 전체. 화면, 교육내용, 링크, 기능, 로고와 글꼴이 들어 있음 | 웹페이지 내용을 바꿀 때 |
| **README.md** | 지금 읽고 있는 사용 설명서 | 사용 방법을 보충할 때 |
| **Pretendard-LICENSE.txt** | 사용 중인 글꼴의 이용 조건 | 그대로 보관 |
| **.nojekyll** | GitHub Pages가 정적 파일을 그대로 제공하도록 하는 설정 파일 | 그대로 보관 |

**웹페이지를 수정하려면 `index.html`을 수정해야 합니다. README만 고쳐서는 웹 화면이 달라지지 않습니다.**

현재 GitHub에 올린 최종본은 한 파일에 모든 것을 넣은 방식입니다. 이전 개발 폴더의 `content.js`, `config.js`, `styles.css`, `preview.html`만 고쳐도 현재 공개 사이트에는 반영되지 않습니다. 이 설명서에서는 현재 저장소의 `index.html`을 기준으로 안내합니다.

## 4. 수정하기 전에 원본을 보관하세요

1. [저장소 첫 화면](https://github.com/circleizt-sketch/Anywhere-Lesson-Plan)의 **Code** 탭을 엽니다.
2. 파일 목록의 **index.html**을 누릅니다.
3. 파일 화면의 **Download raw file** 버튼을 찾습니다. 아래쪽 화살표 모양이거나 파일 도구의 메뉴 안에 있을 수 있습니다.
4. 버튼이 없다면 **Raw**를 눌러 원본을 연 뒤 저장할 수 있습니다.
5. PC에 저장하고 `index-수정전-날짜.html`처럼 알아볼 수 있는 이름으로 보관합니다.

파일이 커서 GitHub 화면에 내용을 표시하지 못한다는 안내가 나와도 다운로드는 할 수 있습니다. 파일 이름이 `index.html.txt`로 바뀌지 않았는지도 확인하세요.

## 5. 무엇을 어디서 수정하나요?

`index.html` 안에는 긴 영어 코드와 로고·글꼴 데이터가 함께 있습니다. 놀라지 마세요. 처음에는 **필요한 문장이나 링크 한 군데만** 수정하는 것이 좋습니다.

| 바꾸려는 내용 | 편집기에서 찾을 검색어 | 설명 |
| --- | --- | --- |
| 자주 묻는 질문(FAQ) | `window.LESSON_FAQ` | 카테고리별 질문·답변. 2026년 운영 안내 기준, 번호는 1~14번 유지 |
| 교육 원문·주제·운영 원칙 | `window.LESSON_CONTENT` | 제목별로 교육내용이 들어 있는 부분 |
| 만족도 조사 주소 | `satisfaction:''` | 현재 미설정. 실제 조사 URL을 받았을 때 입력 |
| 역량진단 주소 | `diagnosis:` | 현재 진단 URL이 들어 있는 부분 |
| 온라인 복습 주소 | `review:` | 현재 온라인 학습 URL이 들어 있는 부분 |
| 첫 화면 메뉴명 | `const MENU=` | 메뉴 이름 목록. 연결 경로는 유지 |
| 학습자 유형 제목·설명 | `const TYPES=` | 신규 학습자·기존 학습자 등 선택지 문구 |
| 교육 종료 전 수업 점검표 문항 | `const COMMON=` 또는 `const DIAG=` | 실제 클릭하는 점검표 문항. 유형별 문항은 `checks` 부분에도 있음 |
| 헤더의 서비스명 | `<span class="service">` | 본문 위 로고 옆의 표시 문구 |
| 색상·간격·글자 체계 | `<style>` | 디자인 코드. 익숙하지 않으면 수정 요청을 맡기는 것이 좋음 |

교육 원문과 화면의 요약·점검표에는 같은 문장이 여러 곳에 있을 수 있습니다. 원문만 바꿨다면 수업 안내와 점검표도 함께 확인하세요. 운영 기준이나 점검 문항을 바꾸는 경우에는 관련 화면 모두를 검토해야 합니다.

### 만족도 조사 링크 바꾸기

1. 편집기에서 **satisfaction:''**를 찾습니다.
2. 빈 작은따옴표 두 개 사이에 재단에서 받은 **실제 HTTPS 주소**를 붙여넣습니다.
3. 앞뒤 작은따옴표와 쉼표·중괄호는 지우지 않습니다.
4. 주소가 아직 없으면 빈 값 그대로 둡니다. 임의의 주소를 넣지 않습니다.
5. 반영 후 **교육자료 바로가기**와 **마무리** 화면에서 링크가 제대로 열리는지 확인합니다.

입력 전 현재 코드는 다음과 같습니다.

```javascript
satisfaction:''
```

실제 주소는 `https://`로 시작해야 합니다. 교육생 이름이나 개인별 인증정보가 포함된 주소를 공개 코드에 넣지 마세요.

### 문장 바꿀 때 주의할 기호

코드 안의 문장은 작은따옴표 또는 큰따옴표로 둘러싸여 있습니다. 문장만 바꾸고 바깥 기호는 유지하세요.

- `\n`은 문장 안의 줄바꿈 표시입니다. 교육 원문 문자열을 바꿀 때 유지하거나 같은 방식으로 사용합니다.
- `{ }`, `[ ]`, 쉼표, 따옴표, `</script>` 같은 표시는 임의로 지우지 않습니다.
- `data:image/png;base64,` 또는 `data:font/woff2;base64,` 뒤의 아주 긴 글자는 로고와 글꼴 데이터입니다. 문장처럼 보이지 않아도 정상이며 직접 수정하지 않습니다.
- 단어가 여러 번 검색되면 한꺼번에 모두 바꾸지 말고, 실제 문장인지 연결 코드인지 확인합니다.

## 6. GitHub 화면에서 간단한 문구 수정하기

**중요: 공개 사이트가 main에 연결되어 있으면 main에 저장한 변경은 자동 배포될 수 있습니다. 초안이나 연습 내용을 바로 저장하지 마세요.**

1. [저장소](https://github.com/circleizt-sketch/Anywhere-Lesson-Plan)를 열고 로그인합니다.
2. **Code** 탭에서 브랜치가 **main**인지 확인합니다.
3. **index.html**을 누릅니다.
4. 오른쪽 위의 **연필 아이콘(Edit this file)**을 누릅니다. 메뉴 안에 있을 수 있습니다.
5. 편집 영역의 찾기 기능으로 위 표의 검색어 또는 바꿀 문장을 찾습니다. Ctrl+F/Mac Command+F로 안 찾아지면 편집기의 찾기 메뉴를 사용하세요.
6. 바꿀 문장이나 주소만 수정합니다.
7. **Preview**가 있더라도 이는 편집 내용이나 차이를 확인하는 화면일 수 있으며, 실제 웹사이트 실행 검토를 대신하지 않습니다.
8. 변경사항을 검토한 뒤 **Commit changes**를 누릅니다.
9. 변경 설명에 `만족도 조사 링크 변경`처럼 무엇을 고쳤는지 씁니다.
10. 검토한 내용을 바로 반영하는 경우 **Commit directly to the main branch**를 선택하고 최종 **Commit changes**를 누릅니다.
11. **Actions**의 Pages 작업이 성공하면 **Visit site**로 들어가 바꾼 부분을 확인합니다.

`Commit`은 ‘수정한 내용을 GitHub에 기록해서 저장하기’라고 생각하면 됩니다.

연필 아이콘이 없으면 로그인 계정의 수정 권한, 브랜치 보호 설정, GitHub의 파일 크기 제한 안내를 확인하세요. 파일이 커서 웹 편집을 지원하지 않는 경우 아래 PC 방법을 사용합니다. 권한이 없다면 저장소 관리자에게 권한을 요청해야 합니다.

## 7. PC에서 먼저 수정·확인한 뒤 올리기

공개 전에 실제 화면을 확인하고 싶다면 이 방법을 사용하세요.

1. 4번 방법으로 현재 GitHub의 **index.html**을 내려받습니다.
2. 원본 백업을 만들고, 수정할 복사본을 준비합니다.
3. VS Code 같은 코드 편집기로 복사본을 엽니다. Word나 한글 문서 편집기로 열어 저장하지 마세요.
4. 필요한 문장이나 주소를 수정하고 저장합니다. **UTF-8 인코딩**, **.html 확장자**를 유지합니다.
5. 저장한 파일을 Chrome 또는 Edge로 열어 실제 화면을 확인합니다. 다운로드 폴더에서 파일을 브라우저 창으로 끌어놓을 수도 있습니다.
6. 브라우저에서 로컬 HTML을 차단한다면, 임의로 보안 설정을 해제하지 말고 허용된 로컬 서버 방식이나 담당자의 검토 환경을 사용하세요.
7. 문제가 없으면 업로드할 파일 이름을 정확히 **index.html**로 맞춥니다.
8. GitHub 저장소의 **Code** 탭에서 **Add file → Upload files**를 누릅니다.
9. 수정한 **index.html 하나를 저장소 맨 바깥 위치에** 올립니다. ZIP이나 파일을 감싼 상위 폴더를 올리지 않습니다.
10. 변경 설명을 쓰고 **Commit changes**로 저장합니다.
11. Actions의 Pages 배포가 성공한 뒤 웹사이트에서 다시 확인합니다.

사이트의 글꼴 라이선스와 `.nojekyll`은 기존 파일을 유지하면 됩니다. 기존 `index.html`과 다른 이름으로 올리면 첫 화면에 반영되지 않습니다. 화면에서 코드를 바꿔둔 경우에는 PC의 오래된 파일로 덮어쓰지 않도록, 수정 작업 직전에 최신 파일을 다시 받으세요.

## 8. 수정 후 꼭 확인할 항목

- 첫 화면의 여섯 개 메뉴가 열리는지
- 신규 학습자·기존 학습자·가입 및 진단 곤란 상황에서 수업으로 이동하는지
- 도입·실습·마무리, 이전·다음 단계와 전체 메뉴 이동이 되는지
- 글자 크게·작게 버튼이 동작하는지
- 교육 종료 전 수업 점검표의 체크와 새 수업 시작이 동작하는지
- 외부 링크가 의도한 페이지로 열리는지
- **한 눈에 보는 지도안 → 인쇄 / PDF 저장**에서 내용이 보이는지
